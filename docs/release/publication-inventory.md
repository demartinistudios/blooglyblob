# Publication inventory

The public repository contains the application, current hardware inputs, build
guide and tools needed to reproduce them. Development source, a hosted guide and
a qualified build kit are separate milestones; use the [release checklist](checklist.md).

## Public selection

| Area | Maintained contents |
| --- | --- |
| Software | Application, scripts, configuration examples, requirements, tests and service definitions; [contributor setup](../../CONTRIBUTING.md) |
| Hardware | Native CAD and exports selected by the [registry](../../hardware/cad/design-control/registry.json), current editable print projects, catalogs, assembly requirements and necessary provenance |
| Guide | One authored `hardware/build-guide/src/` tree; `make guide-build` derives ignored pages and downloads from maintained inputs |
| References | [Component-reference catalog](../../hardware/references/community-20260925/catalog.json) with external publisher links and original measured photographs |
| Media | Assets, source identity, hashes and rights in [asset-manifest.json](asset-manifest.json) |

Personal printer operations, detailed work records, plans and investigations stay
local in ignored folders. Keep credentials, calibration, machine configuration,
experiments, generated guide output and dependency environments out of the public
selection. Public builds must work without those files. Follow the
[hardware retention policy](../../hardware/README.md#retention).

## Readiness and validation scope

[Software validation](../software/validation.md) separates offline coverage from
physical qualification. [Current CAD notes](../../hardware/cad/CURRENT-NOTES.md),
[print guidance](../../hardware/printing/current/README.md) and the
[guide review summary](../../hardware/build-guide/REVIEW.md) describe current
limitations. Pending source comparisons and physical assembly, acoustic and
full-application qualification must not be represented as completed.

`make hardware-check` verifies offline invariants. Run
`python3 hardware/tools/validation/check.py --publication` for the current strict
build-kit blockers. A pending source comparison is missing evidence, not proof of
a defective part. A successful slice or website deployment does not prove fit.

The Pages workflow requires current-input integrity, a guide build and browser
checks. Pending kit reviews are reported separately in its job summary. Local
[preview](../../hardware/build-guide/README.md#build-and-preview) remains available
independently of website deployment and physical qualification.

## Privacy and metadata

Review the intended public files and Git history, including native metadata,
images and packaged downloads. A clean working tree does not sanitize history.
Keep private legacy refs out of public pushes. If a credential is exposed, rotate
it; deleting a file or repository does not invalidate the credential.

Bambu projects and generated downloads must have no nonempty `DesignerUserId`.
The packaging check enforces that narrow rule; it is not a general privacy audit.
The [privacy proof](../../hardware/printing/recipes/project-privacy.json) records
the metadata-only sanitization. Native CAD may retain application resource paths;
review native metadata deliberately and avoid byte edits that corrupt the file or
invalidate accepted input hashes.

## License coverage

[LICENSING.md](../../LICENSING.md) defines grants and exceptions. Original project
software, CAD, print projects, guide materials, photographs and illustrations are
MIT. The two original synthesized sound effects are CC0. Publisher reference
documents retain their rights and are linked externally; they are not bundled
with the source or generated guide. Original project templates remain included.

### Dance song

The project soundtrack and beat data are included under the
[separate soundtrack notice](../../LICENSING.md#project-soundtrack-separate-terms),
not MIT or CC0. They were generated by the repository owner using the ElevenLabs
API. The repository grants no unrestricted music license; standalone music
redistribution or resale is not permitted under the supplied guidance. Keep the
notice with project packages and Pi payloads. Source identity and hashes are in
[asset-manifest.json](asset-manifest.json); private licensing correspondence and
billing records are not part of the public repository.

## Dependency notices

Original-code licensing does not relicense dependencies. The source package and
Pi payload install dependencies separately rather than bundling a Python
environment. A prebuilt image requires a review of its exact binaries, embedded
libraries, notices and corresponding-source obligations.

Known notice considerations for the inspected dependency versions include:

- SoXR/libsoxr: LGPL-2.1-or-later in the inspected 1.1.0 distribution.
- Certifi and development dependency pathspec: MPL-2.0.
- Optional Ring authentication helper: LGPLv3. Optional beat-analysis tools need
  their own review and remain outside the Pi runtime environment.
- rpi-ws281x 5.0.0: BSD-2-Clause in its source license texts despite MIT package metadata.
- Selected pigpiod v79 source: Unlicense; retain its supplied notice.

This list does not exhaustively cover Pi OS or all ARM and optional helper
binaries. Review resolved versions when redistributing a prebuilt environment.
